## Challenges

- **CHALLENGE C1 — H1 / DS3：拒绝前台特例。** “App 已在前台就切线程”仍会改变用户工作上下文，且没有证据能只切到任意目标线程。Q1 已明确要求按 §6.3/D11 调和；统一的单击选中比前后台分支更可预测。
- **CHALLENGE C2 — H7 / DS20 / DS24：不能把 Q2 收回去。** R1 一面接受 P0 尽力而为，一面把 hook 精确审批、跨模式精确计数列为 Phase-1 必过项。采用 P0/P1 分层；D3 的单击手势照旧，能力缺席时不执行。Desktop 默认值不构成“全部能力 P0 保证”。
- **CHALLENGE C3 — H5 / DS11：不接受替换 effort 作用对象。** 改“下次新会话”没有解决 D6 的当前选中目标，反而增加未验证的 deep link effort 参数。正确降级是说明不支持，不能转旋钮后只改一个不会生效的本地数字，也不能写全局 `model_reasoning_effort`。
- **CHALLENGE C4 — F2 / DS1–DS2：稳定性规则要覆盖真实竞态。** Priority 仍决定初次填槽和溢出替换，不能偷偷取消 D10；同时保护选中/钉扎，动作锁定身份与 requestId。300ms 是防快速误触的产品规则，不能替代一次性请求、取消和版本校验；也不应在任意状态动画后重置。
- **CHALLENGE C5 — F3：即时选中与松手判定不可混成一条。** Agent 按下即选中，600ms 追加钉扎；模式键释放才走短按分支。已触发长按后不能再补一次短按，停止也不能等渲染到“100%”才执行。
- **CHALLENGE C6 — F6/F30 / DS16–DS17：Esc 和正则都不是安全证明。** 本轮不把未核实的工具按键写成普适事实；capture-pane 可以辅助诊断，不能独自授权发送 y/Enter。目标和请求无法确定时，禁用比盲打可靠。
- **CHALLENGE C7 — F8–F10 / DS6–DS7：CDC+B 不能补救 HID 泄漏。** 把键设为 `KC_NO` 还须证明 CDC 事件仍存在；F13–F24 也可能被绑定。守护进程不能拦回硬件已经发出的 Option 组合键；VIA 失败不自动授权刷机。PTT 模式切换释放与 F23 冲突，统一以物理释放为准。
- **CHALLENGE C8 — H3/F11/F14 / DS8–DS9：修指标，别把猜测叫硬矛盾。** 整画布一帧可改变多个键，八键不必等于八次传输；600ms 环也无需连续 10–15fps。仍采用单帧切换、离散环和总帧预算以保守交付；不能抢占未证实可中断的传输。
- **CHALLENGE C9 — F13 / DS23 / AC12：死亡进程不会发离线帧。** R1 F13 已正确承认残帧限制，应保留这一点。AC12 的“心跳停止或 offline”不能被解释为骤停后保证刷 offline；心跳冻结和时间戳是过期线索，不是设备看门狗。
- **CHALLENGE C10 — F18 / DS15：停留不是阅读。** 看一行摘要 1.5s 不能代表阅读会话；只选中不清未读。显式聚焦清本地提醒与后端 readState 分开，避免向非稳定数据文件写已读。
- **CHALLENGE C11 — F24/F28 / DS19：身份不能靠缺省和名称猜。** 没有 tmux 变量的 CLI 不是 Desktop；同名 pane 也不是原 pane。删除“7 天后自动丢钉扎”的任意期限，恢复不到就保留无动作的失联占位，不错误绑定。
- **CHALLENGE C12 — F25–F26 / DS12–DS13：只采纳必要的范围缩减。** L1+L4 足够支持固定四技能与模式切换；不因此改 K2 去选槽，也不复制 L3 动态系统到 Phase-1。K2 摘要滚动有独立用途，直接槽键负责选中。
- **CHALLENGE C13 — F32 / DS22：不基于未知事实降级已决策模式。** D9 明确安装在签字后，故不设“签字前五分钟核查”新门槛，也不擅自把 herdr 改为 P1。不可用模式保持在循环中并解释原因。
- **CHALLENGE C14 — F33 / DS5 / AC13：物理来源约束不是同 UID 安全隔离。** 采纳无审批控制接口、设备事件来源校验、SIM 隔离；拒绝“本机任何进程不可能 allow”的绝对表述。抵御主动控制宿主的 agent 需要额外信任边界，不纳入本轮 P0/P1 保证。
- **CHALLENGE C15 — F34 / DS21：逐字节恢复须有前提。** 用户安装后新增的配置也必须保住。无后续编辑时原样恢复，有后续编辑时撤销受管差异；不能为了让 diff 为空把用户新改动覆盖掉。
- **CHALLENGE C16 — R1“不能签字”的总论：区分产品决策与技术实测。** 本轮已为失败分支给出确定行为，未知技术事实不再自动阻塞需求定稿。仍不代替用户签字，也不宣布 PRD 已获批准；硬件/HID/PTT 和动作能力须在后续实现验收前逐项证明。

R1 决策种子的处理均落在上表：DS1–DS24 分别由 F2；F1/F2；Q1/H1；F20/F22；F33；F9/F10；F7/H6；F11/F12/F14/F15；H3；H4；H5；F26；F25；F16/F17；F18；F6；F30；F27/G1；F24；Q2/H7；F34；F32；F13；AC1–AC15 承接。

### P02 · §3.1：状态、映射与未读（F4/F16–F19/AC10）

状态表新增一行，并修改 selected 定义：

| 状态 ID | 含义 | MK20 表达 |
|---------|------|----------|
| `unknown` | 会话身份已知，实时状态无法确认；仍可显式聚焦 | 静态灰底 + `?` + “未知” |
| `selected` | 选中叠加态，不替换基础状态 | 静态双层明暗边框 + 反色名牌 |

> 基础状态共 10 种；selected 为会话叠加态，ptt_listening 为设备按住叠加态。offline 表示后端不可达，unassigned 表示无可操作目标；历史记录或进程存在不构成 idle/running 的证据。精确生命周期/审批状态为 P1 能力。
>
> done_unread 仅由新发生且已可靠关联的完成事件或可信未读回执产生。后端报告已读，或用户显式聚焦确切目标且投递成功时，可清本地提醒；单击选中和停留不清除，不写回后端已读。清提醒后依可得信号恢复基础状态，无法判断则 unknown。error 只由明确的会话/turn 失败产生，普通工具失败不直接等于会话错误。

新增保守映射矩阵（原生枚举名由后续验证补齐，以下表示信号含义）：

| 模式 | 无精确 hooks/等价事件（P0） | 有已关联精确信号（P1） |
|------|---------------------------|------------------------|
| Desktop | 已验证同步的列表：明确 idle→idle、active→粗 running；可验证完成/未读→done_unread；独立实例或历史不证明运行态→unknown；不可达→offline | 在身份、来源及生命周期验证后，明确思考/执行/输入/审批/失败事件分别映射 thinking/running/needs_input/needs_approval/error；缺失或失效信号回 unknown，不补猜 |
| herdr | 已验证 idle→idle、working→粗 running、unknown→unknown；blocked 无明确原因→unknown + 静态待处理提示；done 仅在新完成且未读语义可确认时→done_unread | 可信 hook/原生事件明确 blocked 原因和请求身份后，才拆分 needs_input/needs_approval；其余阶段按明确事件映射 |
| tmux | pane 存在但 agent 状态不明→unknown；pane_current_command、旧提示文本不证明运行/审批；后端不可达→offline；目标消失→无目标 | 经启动登记关联的生命周期/请求事件才映射精确状态；不能关联时仍 unknown |

> 不强制 thinking/running 必须来自 hooks，但必须来自可验证的阶段信号。P1 有多个审批时按 requestId 排队，基础状态显示 needs_approval 并标注数量；unknown 不得自动升级成待审批。

### P04 · §6.3：目标稳定、手势与危险动作（Q1/F1–F5/F21/AC3/AC15）

> Agent 键首次按下立即选中设备上下文，不激活 App、不切换 App 内线程。≤350ms 内同键、同身份第二次按下追加聚焦；长按到 600ms 切换钉扎，释放不再触发点击。命令键单击只执行一次、不连发。模式键短按在释放时判定，长按到点执行后吞掉释放。
>
> 各模式首次按 Priority 填槽；后续已占槽会话不因状态变化在槽内重排。Priority 决定空槽补位及溢出时的候选替换，钉扎及当前选中身份不被挤出。unknown/offline 的低优先级候选排在已知活跃状态之后。不得自动改选；目标消失或身份不可核验时清空选中，目标相关键禁用，不自动选邻居。turn 完成不等于线程消失。
>
> P1 接受和拒绝均保持单击。仅当有有效选中身份和唯一队首 requestId、该请求摘要（工具名与命令首行，至多 40 字）已在副屏显示 ≥300ms，且目标/映射/请求身份稳定 ≥300ms 时生效。显示前截去的内容不声称已完整审阅；有歧义请求交由原生 UI。按下时绑定 mode、会话身份、映射版本和 requestId；执行前失效则取消。拒绝只拒绝这一次请求并返回“Declined via MK20”，不附加停止。请求完成或原生处理后不得重放。
>
> 多请求 FIFO，只处理队首一次，副屏显示 1/N；新队首重新计展示时间。不满足条件的按键立即提示原因，不缓存到条件满足后执行，不提供全部批准。
>
> 停止仍为长按 ≥600ms，一次按住最多中断一次；短按仅提示。按下时锁定目标，期间改选、目标消失或切模式即取消，释放不补发。进度环为最多四段离散进度，600ms 判断与帧发送独立；支持能力只中断当前 turn，不退出进程。

### P06 · §6.5：PTT 与 HID 输入边界（H6/F7–F10/G8/AC6–AC7）

> 仍采用 D8：A 真 HID `KC_RALT` 优先；B 守护进程合成右 Option 仅在当前 IME 和异常释放实测通过后作为回落，两路互斥。若均不可用，显示“PTT 不可用，请使用 Mac 原语音键”，不自动刷机或安装虚拟 HID。
>
> 启用实机控制前，确认 19 个非 PTT 键、两旋钮旋转及按下不产生打字、音量或系统/应用快捷键等副作用。优先用 VIA 设为 KC_NO，但必须同时验证 CDC 所需事件仍保留；F13–F24 不作为默认净化方案。无法消除物理 HID 泄漏时，不得以 CDC 正常或 B 可用宣告整机可用。

>
> B 在释放、断线、睡眠、正常退出时发 up，最长连续合成按住 30s，期限可见；B 的崩溃恢复须通过独立恢复路径实测，否则不启用。A 的释放由真实键和 HID 链路负责，守护进程退出不替代物理松手；分别验证拔线/睡眠后的修饰键状态。

>
> tmux 默认发现 ag-ccai-* / ag-codex-*，也允许显式登记；pane_current_command 仅提供候选。聚焦须同时定位确切 pane/client 并激活其已关联终端 App；未能确认 App 时显示需绑定，不猜默认终端。停止按 adapter、工具及版本验证，优先明确中断能力，验证过的 Esc 才可回落；默认不发 Ctrl-C/kill，不向 idle/unknown composer 盲打。
>
> P1 tmux/herdr 审批首选能唯一指定 requestId 的代答。TUI 回落必须同时验证目标、工具版本、当前请求与专用响应动作；仅 capture-pane 正则不够，无法证明则禁用。

### P09 · §6.7.1：切换、持久化与失联身份（Q3/H3/H4/F22–F24/AC8）

### P11 · §6.8.2：动作不会偷换目标（F1/F4–F6/F20/F30/H5/G5/G9/G11）

### P15 · §7.1、§7.3：静态可读优先（H6/F11–F12/F16/AC10）

> 所有基础状态均须有颜色 + 图标 + 短字的单帧版本；动画为增强，fps 列为各效果期望上限，共享全局预算而非逐键保证。unknown 为静态 ?，offline 为无信号图标，unassigned 为 —。selected 用双层明暗边框和反色名牌，不遮状态图标；取消强制白边脉冲。PTT 波形仅表示观察到按住，不代表 IME 录音已确认。

### P16 · §7.4、§7.5：带宽、反馈和新鲜度（H3/H4/F11/F13–F15/AC1/AC12）

> 总帧率上限仍为 8fps，实际以实机传输/确认/可见延迟和是否支持局部刷新裁剪。下一可发送帧优先级：交互反馈（含选中、模式、停止环）→审批/错误新事件→其它状态变化→装饰动画。不得假设能抢占在途帧；事件执行不等待动画完成。
>
> 模式键+徽章目标 300ms 内反馈；八槽预算内整体更新，取消强制 150ms 扫光。停止环最多四段，不承诺每段准时可见，但 600ms 判定不变。只允许一个注意力动画，其余静态。
>
> 副屏常驻模式/页、能力受限原因和最近更新时间；心跳正常每 2s 更新一次。正常退出/睡眠尽力刷 offline；崩溃或断链可能停留最后画面，冻结的心跳和时间戳表示不能再当实时信息使用，不承诺设备自动生成离线帧。

### P17 · §8：可靠性、安全与配置（F8/F13/F20/F30/F33–F34/G7/G10/G11）

> 可靠性：设备断线、后端断连或版本能力失效时，禁止执行旧目标动作；重连后重新核验身份与请求，不重放按键。A/B 的修饰键恢复分路径验证；崩溃后的设备残帧属于 Phase-1 已知限制，不以“退出清理”覆盖骤停。端口被占时明确提示，要求退出占用程序后重试；不 kill ScreenKey、不抢占端口、不改其自启。
>
> 审批安全（P1）：正常生产路径只从已绑定设备输入链的物理按键产生决定；hook IPC 接收请求并在同一有效请求生命周期回传结果，不开放 approve 或原始按键注入接口。SIM 必须显式启用、明显标记，且不能产生真实审批结果。设备重连、映射/请求变化和重复事件不得复用旧资格。
>
> 安全边界：本产品防止通过其公开接口绕过人工动作，不提供对恶意同 UID 篡改配置、hook 或宿主进程的安全隔离保证。仅屏幕提示不能建立这样的隔离。失败/超时的“不做决定”是交还原生权限系统，不是 allow。
>
> 配置兼容（P1）：安装前备份，幂等添加受管项；卸载在用户未后续编辑时逐字节恢复，有后续编辑时仅撤销受管项并保留冲突备份，不覆盖用户变更。原 notify 独立执行，deck 离线或转发报错不得吞掉原命令。启动能力探测不得发消息、代批准或修改全局配置。
