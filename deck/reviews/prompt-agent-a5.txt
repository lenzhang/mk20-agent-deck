## Part 1 — policy.c/.h (pure, fully unit-tested)
- Action schema (one struct): click/double_click/move/drag(x1,y1,x2,y2)/scroll/type{text}/paste{text}/key{combo}/wait/done/ask_user,
  plus model-reported risk ("low"|"high") and target description string. Validation: type ASCII only (non-ASCII → must use paste);
  paste returns unsupported for now (§3.3); text ≤256 chars; key combo parsed into modifiers+key, unknown key name → reject.
- Risk rules (§3.6), union of local rules and model risk: configurable dangerous-key blacklist (default list from §3.6), type content
  with newline+terminal keywords or sudo/rm/curl|sh etc., target text matching 删除/发送/付款/购买/提交/确认支付/Delete/Send/Pay/Submit
  (case-insensitive, UTF-8 safe), first action of a task, app switch (window title/app change) when enabled.
- Never-do (reject, no confirm channel): password fields/typing into secure input, lock screen/login window, security/privacy settings,
  Screen Sharing / mihomo / proxy settings (window-title blacklist, configurable). Lock screen detected → only HID allowed and every
  type/paste rejected.
- Budgets: max_steps default 30 (cap 100), wall 10 min, model calls 40, per-action exec timeout 2 s; no-progress = 3 consecutive
  identical screenshot hashes → pause + ask user. Model retry: only llm retryable classes, exponential backoff, max 2 retries,
  counted against model-call budget. Non-retryable → task error.
- Config: agent-side /data/mk20/agent/policy.json (path overridable for tests), strict JSON, unknown fields ignored, missing → defaults,
  values clamped to caps; invalid file → defaults + warning (never more permissive than defaults... i.e. a broken file must not
  disable confirmations).

## Part 2 — loop.c/.h state machine with injectable ports
- States exactly: disabled (power-on default) → idle → observing → planning → acting ↔ awaiting_confirm → done | stopped | error.
- Ports (vtable, so tests inject fakes): observe (frame via rfb capture → jpeg, hash, window title/lock hint), model (llm_chat), kbd
  (kbd.sock client: lease.acquire/renew/release, act, ui.agent, confirm.request/confirm.result, events estop/hid.health), clock.
- Implement a real kbd.sock client (kbdc.c) per CTL-PROTOCOL.md (line JSON ≤1024 B, renew before TTL, handle async events).
- Loop: enabled only by kbd "allow" (no API can enable — no such entry point exists in agent code); per step: observe → model (current
  screenshot only + text summary of history, bounded) → policy → (confirm if needed: confirm.request, accept only confirm.result ok;
  cancel/timeout → reject and stop task with stopped/confirm_denied) → act via lease → record step.
- E-stop in ANY state (event from kbd or local stop): cancel in-flight model request (net deadline/cancel flag), release nothing further,
  state=stopped, no further act sent; re-enable only by explicit allow. Lease loss → stop.
- HID/VNC arbitration (§3.3) as a pure sub-state machine: 2 consecutive HID failures → freeze → all-up → switch to VNC input (only
  with an input=vnc lease); 3 consecutive healthy probes → switch back at idle point; never retry the same action on the other channel.
  VNC input sending itself may be a stub port returning unsupported if rfb has no pointer/key event writer yet — say so in NOTES.
- Log line per step to an injectable sink: step no, action type, coords, model id, latency, token usage; type text only length+hash;
  run every log line through a redaction function (Authorization, sk-…, Bearer, secrets contents) — test with grep-style assertions.
