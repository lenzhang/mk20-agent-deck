## Deliverables
1. src/netcfg.c/.h — parse net.json (version 1) exactly as agentcfg.py writes it: profile mac_proxy {proxy.url http://host:port,
   proxy.fallbacks[], routes.domestic/foreign="proxy"} and board_wifi {routes.domestic="direct", foreign "proxy"|"blocked"}; also accept the
   D1' profile "usb_wifi" {mode:"direct"|"proxy", proxy.url when mode=proxy}. FAIL-CLOSED: missing/unreadable/oversize(>16 KiB)/malformed
   file, unknown version/profile/route value, bad URL (only http://host:port, port 1..65535, host = IPv4 literal or hostname <=253),
   mac_proxy with any "direct" route, or "proxy" route without proxy.url → error, and NO socket is ever created. route_for(provider route)
   → {proxy list | direct | blocked}; "direct" is only possible for usb_wifi mode=direct or board_wifi domestic (user-chosen profiles).
   There is no other direct code path anywhere. No egress-IP proof, no mihomo API (D2).
2. src/net.c/.h — HTTPS client:
   - TCP connect with 10 s timeout (non-blocking connect + poll), getaddrinfo for hostnames; overall per-request deadline (default 60 s,
     configurable); every recv/send/handshake step honours the deadline.
   - proxy route: try proxy.url then fallbacks in order, only on connect failure to the proxy itself (never fall to direct). Send
     "CONNECT host:443 HTTP/1.1\r\nHost: host:443\r\n\r\n"; read headers with a hard cap (8 KiB), require "HTTP/1.x 200"; 407/403/other →
     error class "proxy" (status kept). Bytes after the header block in the CONNECT reply → error.
   - mbedTLS over that socket: SNI = target host, verify against CA bundle (default vendor/ca/cacert.pem path configurable, test bundle
     injectable), MBEDTLS_SSL_VERIFY_REQUIRED, hostname check; psa_crypto_init; entropy+ctr_drbg. Verify failures → "tls_verify"
     (expired / not-yet-valid / name mismatch / unknown CA distinguished in detail string), other handshake errors → "tls".
   - HTTP/1.1: one request per connection, "Connection: close", method GET/POST, extra headers (Authorization read from a key file,
     which must be a regular file, not group/other readable (0600/0400), <=4 KiB, trailing whitespace stripped, never logged), body with
     Content-Length. Response: status line + headers (cap 16 KiB), body via Content-Length, chunked, or until-close; body cap (default
     8 MiB, configurable) → "too_large". Keep the response Date header.
   - Error classes (stable strings for the future config page "connection test"): config, blocked, dns, connect, proxy, clock, tls_verify,
     tls, timeout, http_parse, too_large, io. No exit-IP checks.
   - Wipe key/Authorization buffers with mem_wipe after use; free everything on every path.
3. src/clock.c/.h — TLS refuses to start unless the clock is "trusted": wall clock >= a compile-time floor (build date, overridable
   -DMK20_TIME_FLOOR) AND (a sync marker file such as /run/mk20/clock.synced newer than boot, path configurable for tests, OR an explicit
   --trust-clock flag). Time sources: (a) parse an RFC 7231 IMF-fixdate Date header (strict parser, reject obsolete/garbage) — used from
   the proxy/HTTP response; (b) GET http://<mac>/time on the usb0 Mac address returning JSON {"epoch":<int>} (client only; plain HTTP,
   10 s timeout, only to the configured Mac host, never via Wi-Fi). If |skew| > 120 s → settimeofday via an injectable setter (CLI only
   does it with --set-clock; tests use a fake setter), then write the marker. Never skip certificate verification to work around time.
4. CLI in mk20-agent (src/agent_cli.c): `--net-test URL [--net PATH] [--route domestic|foreign] [--key-file PATH] [--ca PATH]
   [--timeout S] [--trust-clock]` → prints one JSON line {ok, class, detail, http_status, bytes, via:"proxy host:port"|"direct"} and never
   the body or headers containing secrets; `--time-sync --mac-host H [--port P] [--set-clock]`. Exit 0 only on HTTP response received.
