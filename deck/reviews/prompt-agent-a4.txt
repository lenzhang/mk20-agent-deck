## Deliverables
1. src/llm.c/.h — the single OpenAI-compatible chat/completions adapter, built on net_request() (POST) + the existing oai.c
   serializer/parser (extend oai.c/.h where needed, keep its existing tests passing).
   - Provider is pure configuration: llm_provider_load(path) parses provider.json exactly as agentcfg.py writes it
     {version:1, provider, model, base_url, domestic, route:"domestic"|"foreign", api_key_file} — fail-closed (regular file <=16 KiB,
     strict JSON via the existing json_util/cJSON, version 1, https base_url via net_https_url, route value valid, key-file path present,
     unknown extra fields ignored). Optional fields: "coord_mode" ("norm1000" default | "pixel"), "max_tokens", "temperature",
     "timeout_ms", "supports_tool_choice", "vision" (bool). base_url is taken from the file (so the GLM coding-plan base
     https://open.bigmodel.cn/api/coding/paas/v4 works without code change). No provider names or URLs hard-coded in llm.c.
   - llm_chat(cfg, netcfg, request{system,user,tools_json,jpeg,jpeg_len,image_w,image_h}, response): builds the body, endpoint
     base_url + "/chat/completions", headers Content-Type: application/json + Authorization via net.c key_file path (net.c already
     reads/wipes the key; do not duplicate the key in llm.c memory if avoidable), route = provider route through netcfg_route_for.
     Response body cap for the model path: 1 MiB (LLM_BODY_MAX), request body cap OAI_BODY_MAX; image <= OAI_IMAGE_MAX.
   - coord_mode: unify to one convention for callers: tool-call arguments x/y (and x2/y2 if present) are returned as screen pixels
     for the given image_w/image_h. norm1000 → oai_norm_to_pixel; pixel → must lie within the image. Out-of-range values: clamp only
     within a small tolerance (≤2% of range, documented), otherwise REJECT the call (error "coord_range"), never silently clamp large errors.
     Non-integer/missing coordinates for tools that declare them → reject that call ("coord_type").
   - Error classification (stable literals, never raw peer data): ok, auth (401/403), rate (429), server (5xx), bad_request (400/404/422),
     timeout, network/proxy/tls/clock (pass through net.c class), too_large (body cap), bad_response (malformed JSON, missing choices,
     missing tool call when the request demanded tool_choice required, invalid arguments JSON, >OAI_TOOLS_MAX calls, oversized fields),
     blocked (route blocked), config. Provide llm_error_name(). Retry policy: none inside llm.c (A5 decides); expose retryable flag
     (rate, server, timeout, network).
   - Kimi A3 #4 carry-over: llm.c MUST NOT enable clock.set_clock (set it to 0 explicitly; add a test asserting the model path never
     calls the clock setter even when a proxy Date with huge skew is present). Time-setting stays only on the usb0 /time path.
   - Kimi A3 #6 carry-over: for Connection:close-delimited bodies, net.c must report whether TLS close_notify was received; on the model
     path a close-delimited body without close_notify is treated as truncated → bad_response class "truncated" (Content-Length/chunked
     unchanged). Add C + pytest coverage. Also Kimi A3 #5 if trivial: read_ca fstat S_ISREG check.
   - Memory: one request at a time, everything freed via llm_response_free; peak RSS documented (see 5).
