## Part 1 — src/mcp.c/.h + src/httpd.c/.h (small single-threaded HTTP/1.1 server)
- Streamable HTTP per MCP 2025-06-18: `POST /mcp` JSON-RPC 2.0 (single message; reject batches with -32600 since 2025-06-18
  removed batching). Responses as `application/json` (no SSE needed; GET /mcp → 405 with Allow: POST). Methods: initialize
  (protocolVersion "2025-06-18", capabilities {tools:{listChanged:false}}, serverInfo mk20-agent), notifications/initialized
  (→ 202 no body), ping, tools/list, tools/call. Unknown method -32601; bad params -32602; parse error -32700. Notifications/
  responses from client → 202. Issue `Mcp-Session-Id` (random, 128-bit hex) on initialize; require it afterwards (missing → 400,
  unknown → 404); DELETE /mcp ends session. Validate `MCP-Protocol-Version` header when present (unsupported → 400).
- Security: `Authorization: Bearer <token>` required on every request (missing/wrong → 401 with WWW-Authenticate: Bearer, constant-
  time compare, no detail). Token file default /data/mk20/secrets/mcp.token: if absent, generate 32 random bytes (getrandom or
  /dev/urandom) hex, write O_CREAT|O_EXCL 0600 tmp → fsync → rename → fsync dir; if present require regular file, 0600, owned by
  service uid, else refuse to start. Reject requests with an Origin header that is not exactly http://172.30.250.2:8765 (DNS
  rebinding). Validate Host. Limits: headers ≤8 KiB, body ≤64 KiB (Content-Length required, no chunked → 411/413), ≤4 concurrent
  connections, per-connection read deadline 5 s, keep-alive allowed but bounded. Never log bodies; log method/tool/status/latency only
  via agent_redact.
- Binding: default 172.30.250.2:8765 with SO_BINDTODEVICE "usb0" (Linux). If bind/bindtodevice fails → refuse to start (fail closed,
  no fallback to wildcard). Never bind INADDR_ANY: reject 0.0.0.0/:: even if passed. A test-only override `--mcp-listen 127.0.0.1:PORT
  --mcp-no-bindtodevice` is accepted only for loopback addresses. Also accept an inherited listening fd for tests if convenient.
- CLI: `mk20-agent --mcp [--mcp-token-file P] [--kbd-sock P] [--policy P] ...` runs the server loop; SIGTERM clean exit.

## Part 2 — tools (one registry, JSON Schema inputSchema for each)
status, screenshot, click, double_click, move, drag, scroll, type_text, key, estop, run_task{goal}, task_status{id}, cancel_task{id}.
- D6: NO tool can enable/allow the agent; there is no such code path. Permission comes only from kbd status (same as A5).
- Every action tool goes through EXACTLY the same policy validation, risk/never-do rules, confirmation flow, input lease, per-action
  deadline and budget accounting as the A5 loop (reuse policy.c/loop/kbdc; add a direct-action entry point in loop.c if needed rather
  than duplicating rules). MCP-driven sessions do not call the model. Coordinates are screenshot pixels of the most recent MCP
  screenshot (require a screenshot first + valid calibration; else error).
- Results: tool errors as `isError:true` content with a short class: disabled (kbd not allowed), stopped (after estop until re-allowed
  at the keyboard), needs_confirmation→denied/timeout, rejected (policy/never-do), budget, busy (a task is running), unsupported
  (paste/VNC input), error. `estop` always works (even when disabled) and sends estop to kbd.
- screenshot: JPEG image content (base64, mimeType image/jpeg) + text with frame/scale info, via the existing RFB capture path
  (existing authenticated RFB connection supplied by runtime; on host use the fake VNC). Respect the existing occlusion/upload-notice
  behaviour if implemented; otherwise note it.
- run_task: single-slot in-process task queue shared design for A7 web (/api/tasks): returns id; when not allowed → disabled (not queued
  executed); task_status returns state/steps summary (no screenshots, no typed text); cancel_task stops it via the loop stop path.
