## Part 1 — web server `--web` (reuse httpd.c; same fail-closed listener rules as MCP)
- Listener default exactly 172.30.250.2:8780 + SO_BINDTODEVICE("usb0"); no fallback; wildcard/IPv6/non-loopback others refused;
  test-only `--web-listen 127.0.0.1:PORT --web-no-bindtodevice`. May run in the same process/event loop as `--mcp` (preferred:
  one poll loop, shared task store) — keep limits (headers 8 KiB, body 64 KiB, 4 conns, 5 s read deadline). Host/Origin checks
  as MCP (Origin must be exactly http://172.30.250.2:8780 when present; for state-changing requests require Origin or
  Sec-Fetch-Site same-origin AND the CSRF token below).
- Pairing (D7/§3.8): `POST /pair/start` generates a 6-digit one-time code (CSPRNG, uniform), valid 5 min, max 5 wrong attempts then
  invalidated; displayed via a pairing display port: real impl sends kbd.sock `screen.text` to the agent control page / secondary
  screen (kbd currently may return rendered:false — treat as "display unavailable", fail closed: no code accepted, report
  `display_unavailable`), test binary (MK20_WEB_TEST like MK20_MCP_TEST) exposes the code via an injected fd only. `POST /pair
  {code}` → session cookie (128-bit random, HttpOnly, SameSite=Strict, Path=/, no Secure since plain http on usb0) + CSRF token;
  max 2 web sessions, 12 h absolute / 30 min idle expiry, power-cycle invalidates (memory only). Constant-time compare.
- Secrets page: `GET /` ~10 KB static HTML (no external deps, CSP default-src 'self'; inline script via hash or none) with the
  pairing + secret form. `POST /secret/{name}` name ∈ provider key files from the provider table + `vnc` (→ vnc.pass); writes
  /data/mk20/secrets/<name>.key (dir configurable for tests) via O_CREAT|O_EXCL 0600 tmp in same dir → full write → fsync → rename →
  fsync dir; refuse symlinked/non-dir parent; value length 1..4096, no NUL/CR/LF. Response only {"set":true,"len":N}. `DELETE
  /secret/{name}`. `GET /secret/{name}` → {"set":bool} only. There is NO endpoint that returns secret contents. Secrets never logged.
- Config: `PUT /config/net` and `PUT /config/provider` → device-side schema validation in C mirroring agentcfg.py (read it; do not
  edit it): reject unknown fields, reject routes.foreign=direct (any profile), proxy url only from the allowed set (Mac 172.30.250.1
  and the other addresses agentcfg allows, or board proxy), base_url must match the provider table; then atomic write
  /data/mk20/agent/{net,provider}.json 0600 (dir 0700). Add a test that parses agentcfg.py's provider table/allowed proxies (python,
  read-only) and asserts the C table matches, so drift is caught. `GET /config/{net,provider}` returns the config with api key paths
  only (never contents). `POST /test` runs the existing net/llm connection test through the configured route (fake provider in tests)
  and returns {ok, latency_ms, error_class}; never direct when profile requires proxy.
- Task API (D5) on the shared single-slot task store from A6: `POST /api/tasks {goal}` → id (while kbd not allowed → queued, state
  `waiting_allow`, not executed; becomes runnable only after keyboard allow; web/API can never allow); `GET /api/tasks/{id}` (state,
  steps with fixed action-name summary, no typed text, no goal echo in logs); `GET /api/tasks/{id}/steps/{n}/shot.jpg` from an
  in-memory ring of last 5 scaled JPEGs (never written to disk, freed on task end+new task); `POST /api/tasks/{id}/pause|resume|stop`
  (stop uses the same kbd revoke/stop path as estop button semantics described in §3.8; if the A5 loop cannot pause safely,
  implement pause as "hold before next observe/act" and document); `GET /api/events` SSE (≤2 clients, bounded buffers, drop slow
  clients). `GET /chat`: ~15 KB static HTML/JS, input box + progress list + screenshot + pause/stop, no external deps.
- All endpoints except GET /, GET /chat, POST /pair/start, POST /pair require a valid paired session (+CSRF for non-GET).
  Unpaired → 401 identical bodies.
